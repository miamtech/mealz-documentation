MealzUIKit UI is SSR HTML/CSS inside the WebView. Branding is applied through **CSS manifests**, not native theme protocols (those belonged to the Older MealzCore stack). Defaults already look fine — register manifests only when you need brand overrides.

## Where to Put Your Files

Mealz already ships SSR + retailer default styles inside the WebView. You only add files for **extra brand overrides**, then register them. `CustomStyle` resolves those paths for you (Android assets / iOS main bundle).

export function StyleFileLocations(props) {
  if (props.platform === "android") {
    return (
      <ul>
        <li>Put manifests and CSS under <code>app/src/main/assets/</code> (for example <code>assets/styles/</code>).</li>
        <li>Register with a path relative to the assets root, e.g. <code>styles/base-manifest.json</code>.</li>
      </ul>
    );
  }
  if (props.platform === "ios") {
    return (
      <ul>
        <li>Put manifests and CSS in the app main bundle (same relative folder layout you will pass to <code>registerManifest</code>).</li>
        <li>Register with that bundle-relative path, e.g. <code>styles/base-manifest.json</code>.</li>
      </ul>
    );
  }
  return (
    <ul>
      <li>Ship the same relative tree on both targets (Android <code>assets/</code> and iOS main bundle), e.g. <code>styles/base-manifest.json</code> + CSS next to it.</li>
      <li>Register once from shared code with that same relative path — <code>CustomStyle</code> already loads from the platform package.</li>
    </ul>
  );
}

<StyleFileLocations platform={props.platform}/>

CSS (and other assets) listed in a manifest’s `links` array are resolved **relative to the directory that contains that manifest**. Keep overrides under that tree — files outside the registered manifest folders are not loaded.

Example layout:

```text
styles/
  base-manifest.json      # links → ./override/base.css
  catalog-manifest.json
  override/
    base.css
    catalog.css
```

## Register a Manifest

export function RegisterManifest(props) {
  if (props.platform === "ios") {
    return (
      <pre><code className="language-swift">{`CustomStyle.companion.getInstance().registerManifest(
    path: "styles/base-manifest.json",
    type: .base
)

// Optionally per feature:
CustomStyle.companion.getInstance().registerManifest(
    path: "styles/catalog-manifest.json",
    type: .catalog
)`}</code></pre>
    );
  }
  return (
    <pre><code className="language-kotlin">{`import ai.mealz.uikit.ui.webview.CustomStyle
import ai.mealz.uikit.ui.webview.ManifestFeatureType

CustomStyle.getInstance().registerManifest(
    path = "styles/base-manifest.json",
    type = ManifestFeatureType.BASE
)

// Optionally per feature:
CustomStyle.getInstance().registerManifest(
    path = "styles/catalog-manifest.json",
    type = ManifestFeatureType.CATALOG
)`}</code></pre>
  );
}

<RegisterManifest platform={props.platform}/>

`ManifestFeatureType` values: `BASE`, `CATALOG`, `PLANNER`, `RECIPE`.

Example manifest:

```json
{
  "updated-at": "2026-01-09T11-26-00",
  "layer": "retailer",
  "links": [
    "./override/base.css"
  ]
}
```
