When your supplier key is in **No Supplier** mode (encoded in the key Mealz provides), Mealz owns the basket. Extra WebView helpers cover retailer/store picking, pricing, and transfer CTAs.

:::important Host Setup
In No Supplier mode, do **not** call `setUser("…")` and do **not** select a store yourself (`setSelectedStoreWithExternalId` / `setSelectedStoreWithMealzId`). Leave authless defaults; retailer and store picking go through [Supplier Selector](#supplier-selector).
:::

## Supplier Selector

Lets the shopper pick an affiliated grocery retailer (and then a store). Mealz opens this automatically when a store is required, or other No Supplier components request it via `redirectToSupplierSelector`. You should not set the Mealz store id manually in the normal flow.

export function SupplierSelectorInitLink(props) {
  return (
    <p>
      See <Link to={`/docs/${props.platform}/overview/initialisation`}>Initialisation → Store</Link>.
    </p>
  );
}

<SupplierSelectorInitLink platform={props.platform}/>

Background: [Non-retailer introduction](/docs/web_ssr/v2/non-retailer-integration/introduction) (steps 3–4 of the transfer journey).

### Parameters

| Parameter | Type | Required | Default | What it does |
|-----------|------|----------|---------|--------------|
| `context` | `SupplierSelectorContext` | yes | — | Why the selector opened. Today: `OpenedForAddToCartByExternalId(externalRecipeId)`. |
| `navigationCallback` | `SupplierSelectorNavigationCallback` | yes | — | Only `exit` matters (cancel or store selected). |
| `modifier` | Compose `Modifier` | no | fills max size | Layout. |
| `stateContent` | state overlays | no | library default | Optional loading UI. |

### `SupplierSelectorNavigationCallback`

| Callback | Required | What you must do |
|----------|----------|------------------|
| `exit` | yes | Dismiss the selector when the user cancels **or** after a store is selected. |

## Recipe Pricing

Shows the price for a recipe in the No Supplier context.

### Parameters

| Parameter | Type | Required | Default | What it does |
|-----------|------|----------|---------|--------------|
| `displayRecipe` | `DisplayRecipe` | yes | — | Mealz or external recipe id (`FromMealzRecipeId` / `FromExternalRecipeId`). |
| `serves` | `Int?` | no | `null` | Portion / guest count for pricing. |
| `navigationCallback` | `RecipePricingNavigationCallback` | yes | — | Opens supplier selector when a store is missing. |
| `modifier` | Compose `Modifier` | no | — | Layout (fixed height). |
| `stateContent` | state overlays | no | library default | Optional loading UI. |

### `RecipePricingNavigationCallback`

| Callback | Required | What you must do |
|----------|----------|------------------|
| `redirectToSupplierSelector` | yes | `(SupplierSelectorContext) -> Unit` — present `SupplierSelectorScreen` with that context. |

See also [Fetching style](/docs/web_ssr/v2/main-features/fetching-style) and [Non-retailer setup](/docs/web_ssr/v2/non-retailer-integration/setup).

## Add to Cart CTA

Primary CTA next to a recipe to add ingredients to the Mealz basket and start transfer toward an affiliated retailer.

Full web behaviour: [no-supplier-add-to-cart-cta (SSR)](/docs/web_ssr/v2/non-retailer-integration/no-supplier-add-to-cart-cta).

### Parameters

| Parameter | Type | Required | Default | What it does |
|-----------|------|----------|---------|--------------|
| `displayRecipe` | `DisplayRecipe.FromExternalRecipeId` | yes | — | **External** recipe id (your content id). |
| `serves` | `Int?` | no | `null` | Guest count for the add-to-cart flow. |
| `navigationCallback` | `AddToCartCtaNavigationCallback` | yes | — | Details, supplier selector, catalog. |
| `modifier` | Compose `Modifier` | no | — | Layout (fixed height). |
| `stateContent` | state overlays | no | library default | Optional loading UI. |

### `AddToCartCtaNavigationCallback`

| Callback | Required | What you must do |
|----------|----------|------------------|
| `goToRecipeDetails` | yes | `(DisplayRecipe, serves: Int?) -> Unit` — open details for that recipe. |
| `redirectToSupplierSelector` | yes | Present supplier selector with the given `SupplierSelectorContext`. |
| `goToCatalog` | yes | `(FeatureRoute.Catalog) -> Unit` — open catalog when requested. |

Base login / store / cart / exit redirects are no-ops on this callback — wire the three callbacks above.

## Basket Count Badges

In No Supplier mode, Mealz owns the basket. Use `BasketCountNotifier` to drive recipe / product count badges in your app chrome.

Register **after** `start`. Multiple listeners are supported — keep a reference to each listener if you need to unregister it later:

export function BasketCountInject(props) {
  if (props.platform === "ios") {
    return (
      <pre><code className="language-swift">{`BasketCountNotifier.shared.registerRecipeCountListener { count in /* badge */ }
BasketCountNotifier.shared.registerProductCountListener { count in /* badge */ }
// Unregister with the same listener instance:
// BasketCountNotifier.shared.unregisterRecipeCountListener(listener:)`}</code></pre>
    );
  }
  return (
    <pre><code className="language-kotlin">{`val recipeListener = BasketCountListener { count -> /* badge */ }
BasketCountNotifier.registerRecipeCountListener(recipeListener)
BasketCountNotifier.registerProductCountListener { count -> /* badge */ }
// Later:
BasketCountNotifier.unregisterRecipeCountListener(recipeListener)`}</code></pre>
  );
}

<BasketCountInject platform={props.platform}/>

Counts are persisted locally and refreshed from WebView observers. They can be stale until a Mealz WebView opens again after process death, auth changes, or store changes without reopening Mealz UI.
